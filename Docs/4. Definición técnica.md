## 2. Glosario de Dominio

| Término | Definición |
|---|---|
| Docente | Profesor/doctor que supervisa tratamientos. Recibe materiales por separado, no está ligado a pacientes. |
| Operador | Estudiante (PRE o POS grado) que realiza tratamientos en pacientes. También llamado "Especialista". |
| Paciente | Persona atendida. Asociado a un operador y un tratamiento. |
| Material | Insumo odontológico consumible (guantes, anestesia, gasa…). Tiene nombre y unidad de medida (texto libre). |
| Unidad (de tratamiento) | Lugar físico de la clínica donde se realiza la atención (Unidad 1, Unidad 2…). No es la unidad de medida del material. |
| Tratamiento Predefinido (Plantilla) | Plantilla de procedimiento con costo sugerido (`Tratamiento_PRED`) y lista de materiales recomendados (`Materiales_List_PRED`). No maneja estados; se usa solo como plantilla. |
| Tratamiento (Instancia) | Atención real a un paciente por un operador. El programa carga la plantilla y crea la primera versión (prellenado automático), que luego se modifica sobre la instancia. Guarda copia del nombre y monto. |
| Materiales_List | Materiales consumidos realmente en un tratamiento (los cargados de la plantilla + los adicionales). |
| Asistencia Docente | Entrega de materiales a un docente en un día específico. Acumulativo diario. |
| Préstamo | (Fase 2) Asignación temporal de un equipo a un operador. |

### 3.4 Multi-clínica

> Modelo de **BD única compartida**: todas las clínicas conviven en la misma base de
> datos y se aíslan por la columna `ClinicaID` presente en cada tabla que pertenece a
> una clínica (catálogos y transacciones). Reemplaza el esquema previo de "instancia
> dedicada" (RD-3.1.7).

#### Clinica

| Columna | Tipo | Restricciones |
|---|---|---|
| ClinicaID | INTEGER | PK, autoincrement |
| Nombre | TEXT | NOT NULL UNIQUE |
| Grupo | TEXT | — ej: 'Pos Grado' |
| Estado | INTEGER | NOT NULL DEFAULT 1 |

#### Columnas ClinicaID por tabla

| Tabla | Columna | Nota |
|---|---|---|
| Clinica | — | tabla de clínicas |
| Operadores | ClinicaID | FK lógica -> Clinica |
| Docentes | ClinicaID | FK lógica -> Clinica |
| Pacientes | ClinicaID | FK lógica -> Clinica |
| Unidad | ClinicaID | FK lógica -> Clinica |
| Tratamiento | ClinicaID | FK lógica -> Clinica |
| Asistencia | ClinicaID | FK lógica -> Clinica |
| RegistroAnulacion | ClinicaID | FK lógica -> Clinica |

> Los catálogos globales (Materiales, Tratamiento_PRED, Unidad_Conversion) no se
> segmentan por clínica.

#### Selección de clínica

- El frontend envía el nombre de la clínica activa en el header HTTP `X-Clinica-Nombre`
  (URL-encoded) en cada petición `/api/*`.
- El backend resuelve el nombre a `ClinicaID`; si el header falta o la clínica no
  existe, responde 400.
- Los servicios y repositorios reciben el `ClinicaID` como parámetro y filtran todas
  las consultas. Por compatibilidad, los constructores/sobrecargas sin `ClinicaID`
  usan el valor por defecto `1`.

## 4. Reglas de Negocio

| ID | Regla | Aplica a |
|---|---|---|
| RD-3.1.1 | **Jerarquía académica**: PRE → tipos {3,4,5}. POS → tipos {R1,R2,R3}. Validar frontend y backend. | Operadores |
| RD-3.1.2 | **Consumo vs inventario**: Materiales se consumen, Equipos se prestan (Fase 2). | Todo el sistema |
| RD-3.1.3 | **Flexibilidad de costo**: El monto del tratamiento puede diferir del sugerido; el valor real es el único válido para reportes. | Tratamiento |
| RD-3.1.4 | **Unicidad diaria docente**: Un solo `Asistencia` activo por docente+fecha. Acumular, no crear nuevo. | Asistencia |
| RD-3.1.5 | **Filtro en reporte especialistas**: Solo tratamientos `CERRADO` cuentan en el reporte de especialistas. | reportes |
| RD-3.1.6 | **Exclusión de anulados**: Registros `ANULADO` no cuentan en ningún reporte. Visible solo en auditoría. | reportes |
| RD-3.1.7 | **Multi-clínica (BD única)**: Todas las clínicas comparten una BD y se aíslan por `ClinicaID`. Cada petición identifica su clínica (header `X-Clinica-Nombre`) y toda consulta filtra por `ClinicaID`; no hay cruce de datos entre clínicas. | arquitectura |
| RD-3.1.8 | **Resiliencia de periodos**: Reporte anual siempre con 12 meses; meses sin datos → cero. | reportes |
| RD-3.1.9 | **Unidades auxiliares**: Las unidades se crean/eliminan físicamente. Si una unidad ocupada se elimina, los tratamientos asociados quedan con UnidadID = NULL. | Unidad |
| RD-3.1.10 | **Periodo del operador**: Cada operador tiene un año (periodo). Solo los del periodo actual aparecen para asignar a tratamientos. Pendiente: definir identificación por DNI en distintos periodos. | Operadores |
| RD-3.1.11 | **Numeración secuencial de unidades**: Al crear una unidad, su UnidadNro se asigna automáticamente como max(UnidadID) + 1. Al eliminar, se libera el número. | Unidad |

### RD adicionales (continuidad, pagos y conversiones)

| ID | Regla | Aplica a |
|---|---|---|
| RD-3.1.12 | **Continuidad**: El tipo (NORMAL/CONTINUO) se establece en la instancia del tratamiento. Un CONTINUO tiene `Monto = 0` fijo (no editable) y `EstadoPago = PAGADO` automático, sin vínculo a un tratamiento padre y sin advertencias de pago. | Tratamiento |
| RD-3.1.13 | **Contabilidad de pagos**: `EstadoPago` se deriva de `MontoPagado` vs `Monto` (persistido). No se prohíbe ejecutar/cerrar un tratamiento sin pago, pero se advierte (excepto CONTINUO). Los pendientes permanecen visibles. | Tratamiento, reportes |
| RD-3.1.14 | **Conversión de unidades**: Todo consumo se suma a la `UnidadBase` del material usando `Unidad_Conversion` al generar reportes. Las cantidades pueden ser decimales (consumo aproximado). | reportes |
| RD-3.1.15 | **Avances como sesiones**: Un avance es una sesión del mismo tratamiento (`Tratamiento_Avance`), no un tratamiento hijo. Cada sesión tiene `Fecha`, materiales (`Materiales_List_Avance`) y un `Pago` opcional que abona al padre. El consolidado de un tratamiento suma la base + las sesiones ACTIVAS. Al anular una sesión se elimina su pago y se recalcula el padre. | Tratamiento |

## 5. Estados del Sistema

### Tratamiento

```
ABIERTO ──→ CERRADO ──→ (visible en reportes)
   │                        │
   └──→ ANULADO ←───────────┘
         (no cuenta en reportes, visible en auditoría)
```

- `ABIERTO`: se pueden agregar materiales adicionales.
- `CERRADO`: bloqueado; solo se puede reabrir explícitamente.
- `ANULADO`: no participa en reportes ni se puede modificar.

Además, todo tratamiento tiene dos atributos independientes del estado:

- Tipo: `NORMAL` o `CONTINUO`. Un `CONTINUO` tiene `Monto = 0` fijo (no editable) y `EstadoPago = PAGADO` automático (absorbido por un tratamiento inicial; no advierte por pago).
- Estado de pago (derivado y persistido): `PENDIENTE` (sin pagos) → `PARCIAL` (0 < MontoPagado < Monto) → `PAGADO` (MontoPagado ≥ Monto). No bloquea ejecución; solo genera advertencia si se ejecuta/cierra sin pago (excepto CONTINUO).

### Asistencia

```
ACTIVO ──→ ANULADO
```

- `ACTIVO`: se pueden acumular materiales durante el día.
- `ANULADO`: no participa en reportes.

## 8. Reportes Excel

### 8.1 Reporte General de Materiales (RF-1.7.2)
- **Columnas**: Material | Unidad (base) | Cantidad Total
- **Fuente**: Suma de `Materiales_List` (de tratamientos CERRADO) + `Materiales_Asistencia` (de registros de Asistencia ACTIVO y no anulados) del mes seleccionado.
- **Conversión**: cada cantidad se multiplica por el `Factor` de `Unidad_Conversion` para expresarse en la `UnidadBase` del material y poder sumarse con cantidades registradas en distintas unidades de empaque.
- **Excluye**: registros ANULADO.

### 8.2 Reporte de Ingresos (RF-1.7.3)
- **Columnas**: Grado | Tipo | Cantidad Tratamientos | Ingreso Total | Monto Pagado | Monto Pendiente
- **Agrupación**: Por `Operadores.Grado` y `Operadores.Tipo`.
- **Fuente**: Suma de `Monto`, `MontoPagado` y `(Monto - MontoPagado)` de tratamientos CERRADO del mes.
- **Nota**: Los tratamientos no pagados no se ocultan; quedan reflejados en la columna `Monto Pendiente`. Un tratamiento CONTINUO (Monto 0) no suma a los ingresos.

### 8.3 Reporte de Consumo Docente (RF-1.7.4)
- **Modalidad consolidado**: Docente | Material | Unidad | Cantidad Total
- **Modalidad detalle diario**: Docente | Día | Material | Unidad | Cantidad
- **Fuente**: `Materiales_Asistencia` de registros de Asistencia ACTIVO del mes.

### 8.4 Reporte de Consumo Especialista (RF-1.7.5)
- **Columnas**: Especialista | Grado | Tipo | Material | Unidad | Cantidad
- **Fuente**: `Materiales_List` de tratamientos CERRADO del mes.
- **Incluye**: materiales precargados de la plantilla y adicionales (todos los de `Materiales_List`).

### 8.5 Reporte Anual (RF-1.7.6)
- **Un solo archivo** con 4 hojas o secciones internas (una por tipo de reporte).
- **Cada sección**: datos desglosados mes por mes durante los 12 meses del año.
- **Mes sin datos**: valores en cero.
- **Excluye**: registros ANULADO.

### Nomenclatura de archivos (RNF-2.3.2)
```
{Materiales,Ingresos,Docente,Especialista,Anual}_{Mes}_{Año}.xlsx
```
Ej: `Materiales_Octubre_2024.xlsx`, `Anual_2024.xlsx`

## 10. Decisiones de Diseño

| # | Decisión | Justificación |
|---|---|---|
| D-01 | SQLite con soporte multi-thread | App local con backend Javalin REST multi-thread. Se recomienda pool de conexiones (HikariCP) para entornos con carga concurrente. |
| D-02 | Flyway para migraciones | Permite versionar el esquema y actualizar BD existentes sin pérdida. |
| D-03 | Buscador predictivo en lugar de dropdown | Catálogo de materiales > 200 ítems (RNF-2.1.2). |
| D-04 | Sin columna `es_predefinido` en `Materiales_List` | Los materiales precargados se copian de la plantilla a la instancia; el reporte usa todos los de `Materiales_List`. No hace falta distinguir origen. |
| D-05 | Borrado lógico (estado ANULADO) en lugar de DELETE | Trazabilidad y auditoría (RF-1.6.3). |
| D-06 | Sin autenticación de usuarios | App local de escritorio single-user empaquetada con Electron. El campo "usuario" en anulaciones usa "SYSTEM" por defecto. Evaluar autenticación si se expone en red. |
| D-07 | Arquitectura orientada a paquetes por capa (model → repository → service → ui) | Clara separación de responsabilidades; facilita testing. |
| D-08 | Sin ORM (SQLite JDBC directo) | SQLite es liviano; un ORM añade complejidad innecesaria para este alcance. |
