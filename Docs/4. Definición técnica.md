## 2. Glosario de Dominio

| Término | Definición |
|---|---|
| Docente | Profesor/doctor que supervisa tratamientos. Recibe materiales por separado, no está ligado a pacientes. |
| Especialista | Estudiante (PRE o POS grado) que realiza tratamientos en pacientes. |
| Paciente | Persona atendida. Asociado a un especialista y un tratamiento. |
| Material | Insumo odontológico consumible (guantes, anestesia, gasa…). Tiene nombre y unidad. |
| Tratamiento Predefinido | Tipo de procedimiento con costo sugerido y lista de materiales recomendados. |
| Tratamiento (Instancia) | Atención real a un paciente por un especialista. Puede tener materiales predefinidos + adicionales. |
| Asistencia Docente | Entrega de materiales a un docente en un día específico. Acumulativo diario. |
| Préstamo | (Fase 2) Asignación temporal de un equipo a un operador. |

## 4. Reglas de Negocio

| ID | Regla | Aplica a |
|---|---|---|
| RD-3.1.1 | **Jerarquía académica**: PRE → tipos {4,5,6}. POS → tipos {R1,R2,R3}. Validar frontend y backend. | especialista |
| RD-3.1.2 | **Consumo vs inventario**: Materiales se consumen, Equipos se prestan (Fase 2). | Todo el sistema |
| RD-3.1.3 | **Flexibilidad de costo**: El monto del tratamiento puede diferir del sugerido; el valor real es el único válido para reportes. | tratamiento |
| RD-3.1.4 | **Unicidad diaria docente**: Un solo `asistencia_docente` activo por docente+fecha. Acumular, no crear nuevo. | asistencia_docente |
| RD-3.1.5 | **Filtro en reporte especialistas**: Solo tratamientos `CERRADO` cuentan en el reporte de especialistas. | reportes |
| RD-3.1.6 | **Exclusión de anulados**: Registros `ANULADO` no cuentan en ningún reporte. Visible solo en auditoría. | reportes |
| RD-3.1.7 | **Instancia dedicada**: Cada clínica tiene su propia BD. Sin filtros de sede. | arquitectura |
| RD-3.1.8 | **Resiliencia de periodos**: Reporte anual siempre con 12 meses; meses sin datos → cero. | reportes |
| RD-3.1.9 | **Unidades auxiliares**: Las unidades se crean/eliminan físicamente. Si una unidad ocupada se elimina, los tratamientos asociados quedan con id_unidad = NULL. | unidad |
| RD-3.1.10 | **Periodo del especialista**: Cada especialista tiene un año (periodo). Solo los del periodo actual aparecen para asignar a tratamientos. Un mismo DNI puede existir en distintos periodos. | especialista |
| RD-3.1.11 | **Numeración secuencial de unidades**: Al crear una unidad, su nombre se asigna automáticamente como "Unidad N" donde N = max(id) + 1. Al eliminar, se libera el número. | unidad |

## 5. Estados del Sistema

### Tratamiento

```
ABIERTO ──→ CERRADO ──→ (visible en reportes)
   │                        │
   └──→ ANULADO ←───────────┘
         (no cuenta en reportes, visible en auditoría)
```

- `ABIERTO`: se pueden agregar materiales adicionales.
- `CERRADO`: bloqueado; solo se puede reabrir explícitamente.
- `ANULADO`: no participa en reportes ni se puede modificar.

### AsistenciaDocente

```
ACTIVO ──→ ANULADO
```

- `ACTIVO`: se pueden acumular materiales durante el día.
- `ANULADO`: no participa en reportes.

## 8. Reportes Excel

### 8.1 Reporte General de Materiales (RF-1.7.2)
- **Columnas**: Material | Unidad | Cantidad Total
- **Fuente**: Suma de `tratamiento_material` (de tratamientos CERRADO) + `asistencia_docente_material` (de registros ACTIVO y no anulados) del mes seleccionado.
- **Excluye**: registros ANULADO.

### 8.2 Reporte de Ingresos (RF-1.7.3)
- **Columnas**: Grado | Tipo | Cantidad Tratamientos | Ingreso Total
- **Agrupación**: Por `especialista.grado` y `especialista.tipo`.
- **Fuente**: Suma de `monto_total` de tratamientos CERRADO del mes.

### 8.3 Reporte de Consumo Docente (RF-1.7.4)
- **Modalidad consolidado**: Docente | Material | Unidad | Cantidad Total
- **Modalidad detalle diario**: Docente | Día | Material | Unidad | Cantidad
- **Fuente**: `asistencia_docente_material` de registros ACTIVO del mes.

### 8.4 Reporte de Consumo Especialista (RF-1.7.5)
- **Columnas**: Especialista | Grado | Tipo | Material | Unidad | Cantidad
- **Fuente**: `tratamiento_material` de tratamientos CERRADO del mes.
- **Incluye**: materiales predefinidos y adicionales.

### 8.5 Reporte Anual (RF-1.7.6)
- **Un solo archivo** con 4 hojas o secciones internas (una por tipo de reporte).
- **Cada sección**: datos desglosados mes por mes durante los 12 meses del año.
- **Mes sin datos**: valores en cero.
- **Excluye**: registros ANULADO.

### Nomenclatura de archivos (RNF-2.3.2)
```
{Materiales,Ingresos,Docente,Especialista,Anual}_{Mes}_{Año}.xlsx
```
Ej: `Materiales_Octubre_2024.xlsx`, `Anual_2024.xlsx`

## 10. Decisiones de Diseño

| # | Decisión | Justificación |
|---|---|---|
| D-01 | SQLite con una sola conexión | App de escritorio single-user; evita overhead de pool de conexiones. |
| D-02 | Flyway para migraciones | Permite versionar el esquema y actualizar BD existentes sin pérdida. |
| D-03 | Buscador predictivo en lugar de dropdown | Catálogo de materiales > 200 ítems (RNF-2.1.2). |
| D-04 | `es_predefinido` boolean en `tratamiento_material` | Permite distinguir materiales sugeridos de adicionales para reportes. |
| D-05 | Borrado lógico (estado ANULADO) en lugar de DELETE | Trazabilidad y auditoría (RF-1.6.3). |
| D-06 | Sin autenticación de usuarios en MVP | App local; el campo "usuario" en anulaciones puede ser un nombre configurable o un prompt al inicio. |
| D-07 | Arquitectura orientada a paquetes por capa (model → repository → service → ui) | Clara separación de responsabilidades; facilita testing. |
| D-08 | Sin ORM (SQLite JDBC directo) | SQLite es liviano; un ORM añade complejidad innecesaria para este alcance. |

## 11. Decisiones Tomadas

| Decisión | Resolución |
|---|---|
| **Editar después del cierre** | ✅ Permitido sin reapertura explícita. Se edita directamente. |
| **Usuario en anulaciones** | ✅ Se pide nombre + descripción opcional al anular. Se almacena fecha/hora automática. |
| **Nro. historia paciente** | ✅ Opcional (campo en tabla, no obligatorio). |
| **Reporte docente — detalle diario** | ✅ Incluir consolidado mensual + desglose diario desde la primera versión. |
| **Unidades: gestión persistente** | ✅ Tabla `unidad` en BD con FK `ON DELETE SET NULL`. |
| **Unidades: eliminación** | ✅ Solo si está libre. Bloqueado si ocupado. |
| **Especialista: periodo** | ✅ Campo `periodo` en la entidad. Autocompletado con año actual, editable. |
| **Búsqueda predictiva** | ✅ Sin botón. Filtrado en tiempo real sobre toda la lista. Dropdown con resultados al tipear. |
| **Unidades: numeración** | ✅ Secuencial automática. Al eliminar, el número se reasigna. |
